# Inventory Service — Go + MongoDB: транзакции, Clean Architecture и Swagger

Практический пример backend-микросервиса на **Go**, который показывает, как построить сервис управления складским инвентарём с использованием **MongoDB, транзакций, Clean Architecture, Docker и Swagger**.

Проект можно использовать не только как демонстрацию технологий, но и как **готовую основу для изучения и переноса отдельных решений в собственные Go-сервисы**.

## 🎯 Что вы получите от проекта

Изучая этот проект, вы сможете увидеть на практике, как:

* организовать Go-проект по принципам **Clean Architecture**;
* разделить HTTP, бизнес-логику и работу с базой данных;
* реализовать REST API для работы с товарами;
* работать с **MongoDB из Go**;
* использовать **MongoDB Replica Set**;
* выполнять операции внутри **транзакций MongoDB**;
* создавать репозитории для доступа к данным;
* добавлять индексы и работать с ними;
* документировать API с помощью **Swagger**;
* запускать приложение и MongoDB через **Docker Compose**;
* настроить окружение для разработки с **Air и Live Reload**;
* быстро проверить API через `curl` или Swagger UI.

## 🧩 Что реализовано

Сервис предоставляет API для управления складскими товарами.

Основные возможности:

* создание товара;
* получение товара по SKU;
* получение списка товаров;
* получение аналитики;
* работа с MongoDB;
* транзакционная обработка операций;
* индексация данных;
* Swagger-документация API.

Архитектура проекта разделяет ответственность между HTTP-слоем, бизнес-логикой и хранилищем данных, поэтому отдельные части приложения проще заменять, тестировать и расширять.

## 🏗 Архитектура

Проект построен с использованием подходов **Clean Architecture**.

Это позволяет отделить:

```text
HTTP / API
    ↓
Application / Business Logic
    ↓
Repository
    ↓
MongoDB
```

Такой подход помогает не связывать бизнес-логику непосредственно с MongoDB или HTTP-фреймворком.

Например, в собственном проекте можно заменить MongoDB на другое хранилище, не переписывая всю бизнес-логику приложения.

## 📦 Работа с API

### Создание товара

```bash
curl -X POST http://localhost:8080/products \
     -H "Content-Type: application/json" \
     -d '{"name": "iPhone 15", "sku": "apple-15", "price": 999.99, "quantity": 10}'
```

Пример ответа:

```json
{
  "id": "69c39d5e7d29a894c5559204",
  "name": "iPhone 15",
  "sku": "apple-15",
  "price": 999.99,
  "quantity": 10,
  "updated_at": "2026-03-25T08:31:26.9049421Z"
}
```

### Получение товара по SKU

```bash
curl http://localhost:8080/products/apple-15
```

### Создание нескольких товаров

```bash
curl -X POST http://localhost:8080/products \
     -H "Content-Type: application/json" \
     -d '{"name": "iPhone 15", "sku": "iphone", "price": 1000, "quantity": 10}'

curl -X POST http://localhost:8080/products \
     -H "Content-Type: application/json" \
     -d '{"name": "Samsung S24", "sku": "samsung", "price": 900, "quantity": 10}'
```

### Получение списка товаров

```bash
curl "http://localhost:8080/products?limit=1&offset=1"
```

### Получение аналитики

```bash
curl -i "http://localhost:8080/products/analytics"
```

## 🗄 Работа с MongoDB

Проект запускает MongoDB в Docker и использует **Replica Set**, необходимый для работы транзакций MongoDB.

Подключиться к MongoDB можно следующим образом:

```bash
docker exec -it mongodb_inventory mongosh
```

Выберите базу данных:

```javascript
use inventory_db
```

Получите товары:

```javascript
db.products.find({ sku: "iphone" })
db.products.find({ sku: "samsung" })
```

Получить все товары:

```bash
docker exec -it mongodb_inventory mongosh inventory_db --eval "db.products.find()"
```

Посмотреть индексы:

```bash
docker exec -it mongodb_inventory mongosh inventory_db
```

```javascript
db.products.getIndexes()
```

## 🔄 MongoDB Transactions

Одна из практических целей проекта — показать использование **транзакций MongoDB в Go-приложении**.

Это полезно для сценариев, где несколько изменений в базе должны рассматриваться как одна атомарная операция.

Например:

```text
Начало транзакции
       ↓
Изменение данных
       ↓
Дополнительная операция
       ↓
Commit
```

Если операция завершается ошибкой, изменения можно откатить:

```text
Начало транзакции
       ↓
Изменение данных
       ↓
Ошибка
       ↓
Rollback
```

Такой подход можно адаптировать для складских операций, заказов, платежных процессов и других сценариев, где важно сохранить согласованность нескольких изменений.

## 🔥 Live Reload

Для разработки используется **Air**.

При изменении исходного кода приложение автоматически пересобирается и перезапускается.

Это позволяет быстрее экспериментировать с API, бизнес-логикой и MongoDB, не перезапуская сервис вручную после каждого изменения.
